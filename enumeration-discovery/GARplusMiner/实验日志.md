## 2026/7/7 修改记录：消融实验、tau 参数实验与覆盖率统计

### 1. `run_ablation_study.py`

目的：

- 将消融实验改成更适合 Slurm 并行运行的形式：一次只跑一个数据集和一个配置组合。
- 支持通过命令行参数设置数据集、消融变体和最大 pattern 节点数。
- 修正 `wo_order_embedding` 的输入图逻辑，避免只读取前 50 行导致 pattern 无法扩展。
- 重新定义 LogicGAR / NeuralGAR 两个消融变体，使其与论文描述一致。

主要修改：

- 增加命令行参数：

```bash
--dataset
--ablation
--max-pattern-nodes
```

- `wo_order_embedding` 中新增：

```python
"max_rows": None
```

含义是：当该变体关闭 sampled/order-embedding 输入、改用 CSV/full graph loader 时，必须读完整图，否则 DDA/TI/PPI 都可能因为 `max_rows=50` 导致过滤后边数太少，无法生成 pattern。

- 修正 `wo_order_embedding` 的 CSV loader：

```python
"csv_graph_loader": cfg.csv_graph_loader or cfg.verification_graph_loader
```

避免 DDA/TI 只有 `verification_graph_loader` 时直接报错。

- 重新定义消融变体：

```text
wo_neuralgar / logicgar_only:
    只保留结构和属性谓词，关闭 ML 谓词。

wo_logicgar / neuralgar_only:
    只保留 ML 谓词，删除结构、节点属性、原始边属性等非 ML 谓词。
```

效果：

- Slurm 中可以直接用：

```bash
python run_ablation_study.py \
  --dataset DDA \
  --ablation full \
  --max-pattern-nodes 4
```

- `wo_order_embedding` 不再因为只读 50 行导致图里只剩 1 条边。
- LogicGAR-only 和 NeuralGAR-only 的消融边界更清楚，符合论文中：

```text
LogicGAR: structural and attribute predicates only
NeuralGAR: ML predicates only
```

### 2. `predicate_selection.py`

目的：

- 增加“谓词白名单”能力，用于实现真正的 NeuralGAR-only。
- 原先只有黑名单 `drop_feature_key_tokens`，容易漏掉 PPI/DDA/TI 中没有显式列出的原始属性字段。

主要修改：

- 新增参数：

```python
keep_feature_key_tokens
```

- 过滤逻辑变为：

```text
如果 keep_feature_key_tokens 非空：
    只有 key 中包含白名单 token 的谓词会被保留。
否则：
    使用原来的 drop_feature_key_tokens 黑名单逻辑。
```

- 目标标签 `y_key` 永远保留，不会被白名单误删。

效果：

- `neuralgar_only` 可以严格只保留：

```text
ml_
similarity
equivalence
```

- 不再出现 `e0.bn_edge_semantic`、`v0.xxx`、`e1.xxx` 等逻辑/属性谓词混入 NeuralGAR-only 的问题。
- 默认 `keep_feature_key_tokens=()`，所以普通实验和 full 模式不受影响。

- 修复 `_rule_matches_row()` 中 `!=` literal 被覆盖的问题。

方便检查当前实验到底是黑名单过滤还是白名单保留。

### 5. `BNlearning/pattern_bn_features.py`

目的：

- 修复 PPI 全量图中存在 self-loop 时，`networkx.core_number()` 报错的问题。
- 该问题在 `wo_order_embedding` 改为读全量 CSV 后暴露出来。

报错信息：

```text
networkx.exception.NetworkXNotImplemented:
Input graph has self loops which is not permitted
```

主要修改：

- 在 `augment_graph_structural_features()` 中，对临时 `networkx.Graph()` 删除 self-loop：

```python
undirected.add_nodes_from(graph.vertices.keys())
self_loops = list(nx.selfloop_edges(undirected))
if self_loops:
    undirected.remove_edges_from(self_loops)
```

注意：

- 这里只修改用于计算结构特征的临时 networkx 图。
- 不删除原始 `DataGraph` 中的边。
- 不影响 pattern matching / VSpawn / rule mining 的输入图结构。

效果：

- PPI 全量图存在 self-loop 时也能正常计算：

```text
degree
clustering_bin
core_bin
role
degree_bucket
```

- `wo_order_embedding` 在 PPI 上不再因为 self-loop 卡在结构特征增强阶段。

### 6. 当前 tau 参数实验逻辑说明

当前 `run_tau_sensitivity.py` 中：

```python
TAU_P_VALUES = (0.0, 0.05, 0.10, 0.20, 0.30, 0.50)
TAU_X_VALUES = (0.0, 0.02, 0.05, 0.10, 0.20, 0.30)
TAU_P_SWEEP_RELATIVE_TAU = None
```

含义：

- `tau_P` 控制 Pattern-BN 的 pattern extension 剪枝阈值。
- `tau_X` 控制 Predicate-BN 的 predicate / feature 剪枝阈值。
- `relative_tau` 是 Pattern-BN 的相对阈值，逻辑近似为：

```text
实际阈值 = max(tau_p, relative_tau * 当前候选最高分)
```

在 `tau_P` sweep 中将 `relative_tau=None`，是为了避免相对阈值盖过绝对 `tau_P`，使不同 `tau_P` 设置看不出差异。
