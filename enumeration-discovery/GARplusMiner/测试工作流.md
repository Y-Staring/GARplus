# 测试工作流

本文档给下一个 agent / 合作者使用，说明修改后的代码如何测试、每个实验脚本负责什么、远程写过的代码在本地是否已经同步，以及上传 GitHub 前需要检查什么。

本文档中的路径默认以两个位置为基准：

```text
Git 仓库根目录: GARplus/
算法目录: enumeration-discovery/
GARplusMiner 目录: enumeration-discovery/GARplusMiner/
```

远程运行时请先设置自己的路径变量，后续命令都用变量和相对路径表示：

```bash
export REPO_ROOT=/path/to/enumeration-discovery
export GARPLUS_ROOT=/path/to/GARplus
export REPO_ROOT=$GARPLUS_ROOT/enumeration-discovery
export MINER_DIR=$REPO_ROOT/GARplusMiner
export PY=/path/to/python
cd "$MINER_DIR"
```

## 8. Ablation 负边导出测试

相关文件：

```text
GARplusMiner/batch_expand_ablation_negative_edges.py
GARplusMiner/negative_edge_expander.py
```

重要修复：

```python
rule.predicted_label == config.negative_value
```

修复目的：

- `candidate_non_edges` 之前可能把 `positive` consequent 规则也导出到 `negative_edges_only_*.csv`。
- 修复后只允许 `predicted_label=negative` 的规则导出。

测试命令：

```bash
cd "$MINER_DIR"
"$PY" batch_expand_ablation_negative_edges.py \
  --datasets DDA \
  --variants logicgar_only \
  --mode candidate_non_edges \
  --overwrite
```

重跑后检查输出 CSV：

```bash
python - <<'PY'
import csv
from collections import Counter

path = "ablation_negative_edges_only/dda/logicgar_only/negative_edges_only_candidate_non_edges.csv"
counts = Counter()
with open(path, newline="", encoding="utf-8-sig") as f:
    for row in csv.DictReader(f):
        counts[row.get("predicted_label", "")] += 1
print(counts)
PY
```

预期：

```text
Counter({'negative': N})
```

不应再出现：

```text
positive
```

如果仍然出现 `positive`：

- 运行的不是修复后的 `negative_edge_expander.py`。
- 或 batch 使用了另一个仓库路径。

PPI 注意事项：

- PPI 在 `candidate_non_edges` 模式下可能仍然导出 0 条。
- 如果 summary 中有：

```text
matched_synthetic_instances=0
exported_new_pairs=0
```

表示候选非边没有匹配规则前件，不是脚本失败。

PPI 可以改试：

```bash
--mode anchored_existing_edge_labeling
```

或：

```bash
--mode matched_existing
```

## 9. 噪声鲁棒性 denoise 测试

相关文件：

```text
GARplusMiner/apply_gar_rules_to_noisy_graph.py
GARplusMiner/negative_edge_expander.py
GARplusMiner/gar_denoise_noise_only_probe.py
GARplusMiner/gar_denoise_probe_runner.py
```

正式单文件测试：

```bash
cd "$MINER_DIR"
"$PY" apply_gar_rules_to_noisy_graph.py \
  --dataset DDA \
  --input-noisy-csv ../experiments/exp1_accuracy/DDA_test/data/noise/drug_disease_5pct.csv \
  --output-dir ../experiments/exp1_accuracy/denoise_test/dda_5pct \
  --noise-only \
  --min-rule-confidence 0.8 \
  --min-rule-lift 2.0
```

TI 建议阈值：

```bash
--min-rule-confidence 0.8 --min-rule-lift 1.0
```

原因：

- TI 在 `lift=2.0` 时可用简单负规则为 0 条。
- `conf=0.8,lift=1.0` 仍有可用负规则。

输出文件：

```text
*_gar_cleaned.csv
*_gar_removed_edges.csv
*_gar_marked_all.csv
*_gar_denoise_summary.csv
```

检查是否只删除 `noise_label=1`：

```bash
python - <<'PY'
import csv
from collections import Counter

path = "../experiments/exp1_accuracy/denoise_test/dda_5pct/dda_gar_removed_edges.csv"
c = Counter()
with open(path, newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        c[row.get("noise_label", "")] += 1
print(c)
PY
```

预期：

```text
Counter({'1': N})
```

批量探针：

```bash
cd "$MINER_DIR"
"$PY" gar_denoise_noise_only_probe.py ../experiments/exp1_accuracy/gar_denoise_noise_only_probe DDA TI
```

说明：

- 该探针会临时生成配置副本，不修改源 noisy CSV。
- DDA 默认使用 `min_conf=0.8,min_lift=2.0`。
- TI 默认使用较宽阈值，用于确认 `--noise-only` 流程是否只删噪声边。
